= 2. Architecture Constraints



== 2.1. Technical Constraints

[cols="1,2,2", options="header"]
|===
| Constraint
| Description
| Impact

| Java 21 Requirement
| Must use Java 21 or later for language features and compatibility
| Limits Java version choices, enables modern language features

| Gradle Build System
| Must use Gradle as the build tool (version 8.5+)
| Standardizes build configuration across modules

| Kafka Dependency
| Must use Apache Kafka as event backbone
| All modules must integrate with Kafka

| JSON Serialization
| First iteration uses JSON for event serialization
| Human-readable, but less efficient than binary formats

| Plain Java Preferred
| Use plain Java where simpler, Spring Boot optional
| Reduces dependencies, focuses on core concepts

| Separate Implementations
| Maintain separate implementations for each technology
| Enables direct comparison, may lead to code duplication
|===

== 2.2. Organizational Constraints

[cols="1,2,2", options="header"]
|===
| Constraint
| Description
| Impact

| Learning Focus
| Primary goal is learning and understanding, not production
| Simplifies implementation, prioritizes clarity over completeness

| Single Maintainer
| Project maintained by Integration Architecture Team
| Centralized decision-making, limited resources

| Open Source
| Project is open source under MIT License
| Public visibility, community contributions possible

| Time Constraints
| Project has development timeline and milestones
| Prioritizes high-value features, defers nice-to-haves
|===

|===
| Constraint
| Description
| Impact

| Must follow arc42 architecture documentation template

| YAML Front Matter
| All documentation files must include YAML metadata
| Enables tooling, traceability, machine processing

| Must use semantic anchors for cross-referencing
| Enables precise linking, improves navigation

| Must use PlantUML for architecture diagrams

| Comprehensive architecture coverage
|===
