Kafka -> Esper : Deliver OrderCreated event
Kafka -> Flink : Deliver OrderCreated event
Kafka -> FlinkCep : Deliver OrderCreated event

Clock -> Esper : Timer ticks (1 minute intervals)
Clock -> Flink : Watermarks advance
Clock -> FlinkCep : Watermarks advance

Esper -> Esper : Check for missing PaymentReceived
Flink -> Flink : Window expires without PaymentReceived
FlinkCep -> FlinkCep : Pattern timeout triggers

Esper -> Esper : Fire timeout detection rule
Flink -> Flink : Emit timeout detection result
FlinkCep -> FlinkCep : Emit timeout detection result

@enduml
----

*Steps:*
. OrderCreated event is received
. No PaymentReceived event is received within the timeout period (5 minutes)
. Each technology detects the timeout using different mechanisms:
   - Esper: Timer-based EPL with NOT EXISTS clause
   - Flink Basic: Window-based processing with state checking
   - Flink CEP: Pattern with time constraints and NOT NEXT

*Technologies Involved:*
- [semantic-anchor: technology.esper] (Timer-based rules)
- [semantic-anchor: technology.flink] (Windowing and watermarks)
- [semantic-anchor: technology.flink-cep] (Pattern timeout)

=== Order Cancellation Flow [semantic-anchor: scenario.order-cancellation]

*Steps:*
. OrderCreated event is processed
. OrderCancelled event is published (due to customer request or timeout)
. Consumers receive OrderCancelled event and process it accordingly
. Different handling:
   - Kafka Consumer: Simple logging and cache cleanup
   - Esper: Pattern detection for order cancellation
   - Flink Basic: Stateful processing of cancellation
   - Flink CEP: Pattern matching for cancellation flows

=== Shipment Start Flow [semantic-anchor: scenario.shipment-start]

*Steps:*
. OrderCreated and PaymentReceived events are processed
. ShipmentStarted event is published
. Consumers receive ShipmentStarted event
. Correlation with previous events:
   - Kafka Consumer: Manual correlation using cached order and payment
   - Esper: Pattern detection for complete order-to-shipment flow
   - Flink Basic: Stateful processing validating shipment follows payment
   - Flink CEP: Pattern detection for complete flow

== Error Scenarios

=== Event Deserialization Failure

*Cause:* Malformed JSON or unknown event type
*Detection:* EventSerializer.deserialize() throws exception
*Handling:* Log error, skip event, continue processing
*Impact:* Single event loss, processing continues
*Recovery:* Fix event format, replay from offset

=== Kafka Connection Failure

*Cause:* Kafka broker unavailable
*Detection:* Kafka client throws exception
*Handling:* Retry with exponential backoff, log error
*Impact:* Processing paused until connection restored
*Recovery:* Restart consumers when Kafka available

=== Esper Rule Compilation Error

*Cause:* Invalid EPL syntax
*Detection:* Exception during EPL statement creation
*Handling:* Fail fast, log detailed error
*Impact:* Engine fails to start
*Recovery:* Fix EPL syntax, restart engine
