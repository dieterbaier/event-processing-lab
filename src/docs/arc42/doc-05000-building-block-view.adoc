== Level-1: Module Structure

The project follows a modular architecture with clear separation of concerns:

----

skinparam monochrome true

== Level-2: Module Details

=== Event Model Module

[cols="1,2", options="header"]
|===
| Aspect
| Description

| Purpose
| Common event DTOs and serialization

| Responsibilities
| Define event types, provide serialization/deserialization

| Interfaces
| Event, EventType, EventSerializer, EventFactory

| Data
| OrderCreated, PaymentReceived, PaymentFailed, OrderCancelled, ShipmentStarted

| Quality
| Reusable, type-safe, JSON-serializable

|===

[plantuml,event-model,png]
----
@startuml
skinparam monochrome true

class Event {
    +String eventId
    +String eventType
    +Instant timestamp
    +String version
    +getEventTypeEnum()
}

class EventType {
    ORDER_CREATED
    PAYMENT_RECEIVED
    PAYMENT_FAILED
    ORDER_CANCELLED
    SHIPMENT_STARTED
}

class EventSerializer {
    +serialize(Event)
    +deserialize(String)
}

class EventFactory {
    +createRandomOrderCreated()
    +createRandomPaymentReceived()
    +createRandomPaymentFailed()
    +createRandomOrderCancelled()
    +createRandomShipmentStarted()
}

Event <|-- OrderCreated
Event <|-- PaymentReceived
Event <|-- PaymentFailed
Event <|-- OrderCancelled
Event <|-- ShipmentStarted

@enduml
----

=== Event Producer Module

[cols="1,2", options="header"]
|===
| Aspect
| Description

| Purpose
| Generate and publish events to Kafka

| Responsibilities
| Event generation, Kafka production, rate control

| Technology
| Kafka Producer API

| Configuration
| Bootstrap servers, topic, rate

| Quality
| Reliable, configurable, observable

|===

[plantuml,event-producer,png]
----
@startuml
skinparam monochrome true

class OrderEventProducer {
    +KafkaProducer producer
    +String topic
    +int eventsPerSecond
    +start()
    +stop()
    +sendEvent(Event)
    +produceEvent()
}

class ProducerConfig {
    +String bootstrapServers
    +String topic
    +String clientId
    +int eventsPerSecond
    +fromEnvironment()
}

OrderEventProducer --> Kafka : "publishes to"
OrderEventProducer --> EventSerializer : "uses"
OrderEventProducer --> EventFactory : "uses"

@enduml
----

=== Esper CEP Module

[cols="1,2", options="header"]
|===
| Aspect
| Description

| Purpose
| Complex Event Processing with Esper

| Responsibilities
| EPL rule definition, pattern detection, event correlation

| Technology
| Esper 8.7.0, Kafka Consumer

| Patterns
| Order creation, payment processing, timeout detection, complete flows

| Quality
| Rule-based, declarative, efficient

|===
