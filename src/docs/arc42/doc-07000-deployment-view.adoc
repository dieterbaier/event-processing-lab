= 7. Deployment View



== 7.1. Deployment Overview

The Event Processing Lab is designed for **local development and learning**. Deployment focuses on simplicity and ease of setup rather than production-grade scalability and fault tolerance.

== 7.3. Development Environment

=== Docker Compose Configuration

A `docker-compose.kafka.yml` file provides the Kafka infrastructure:

[source,yaml]
----
version: '3.8'

services:
  zookeeper:
    image: confluentinc/cp-zookeeper:7.4.0
    hostname: zookeeper
    container_name: zookeeper
    ports:
      - "2181:2181"
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181
      ZOOKEEPER_TICK_TIME: 2000

  kafka:
    image: confluentinc/cp-kafka:7.4.0
    hostname: kafka
    container_name: kafka
    depends_on:
      - zookeeper
    ports:
      - "9092:9092"
    environment:
      KAFKA_BROKER_ID: 1
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: PLAINTEXT:PLAINTEXT,PLAINTEXT_INTERNAL:PLAINTEXT
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092,PLAINTEXT_INTERNAL://kafka:29092
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1
      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0
    volumes:
      - kafka-data:/var/lib/kafka/data

volumes:
  kafka-data:
----

== 7.6. Deployment Constraints

[cols="1,3", options="header"]
|===
| Constraint
| Description

| Local Development Focus
| Deployment optimized for local development and learning

| Single Node
| All components run on a single machine

| Minimal Infrastructure
| Only Kafka infrastructure required beyond Java

| Manual Scaling
| Scaling requires manual configuration changes

| No High Availability
| Single instance of each component, no redundancy
|===
