= 1. Introduction and Goals

[semantic-anchor: event-processing-lab]

== 1.1. Purpose

The Event Processing Lab is a **learning project** designed to enable integration architects to understand, compare, and master different event processing technologies through hands-on experience with a common use case.

By implementing the same business scenarios across multiple technologies, this project provides direct comparison of:

* Architectural trade-offs
* Scalability characteristics
* Operational complexity
* State handling approaches
* Rule and pattern complexity

== 1.4. Project Scope

=== In Scope

* Event processing technologies: Kafka, Esper, Apache Flink, Flink CEP
* Use case: Order lifecycle (OrderCreated, PaymentReceived, PaymentFailed, OrderCancelled, ShipmentStarted)
* Scenarios: Order creation, payment processing, payment timeout, order cancellation, shipment start
* Documentation: Complete arc42 architecture documentation
* Architecture: Multi-module Gradle project with clear separation of concerns

=== Out of Scope

* Production-grade deployment and operations
* Enterprise security features
* High-availability configurations
* Performance optimization for production
* Binary serialization formats (Avro, Protobuf) in first iteration
* Spring Boot integration (optional, not required)
