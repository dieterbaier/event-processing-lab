# ADR-003: Keep Spring Boot Optional, Use Plain Java Where Simpler

[semantic-anchor: decision.plain-java-over-spring]

## Status
✅ Accepted

## Context

The Event Processing Lab aims to demonstrate the core capabilities of different event processing technologies (Kafka, Esper, Flink, Flink CEP). When implementing the examples, we must decide whether to use Spring Boot or plain Java.

The decision affects:
- Dependency complexity and project size
- Learning focus (technology vs. framework)
- Code readability and simplicity
- Setup and configuration overhead
- Testing complexity

## Decision

**Prefer plain Java implementations where simpler, keeping Spring Boot as an optional approach for specific scenarios where it provides clear value.**

## Decision Drivers

| Driver | Importance | Notes |
|--------|------------|-------|
| Focus on Core Concepts | High | Examples should demonstrate event processing, not Spring |
| Dependency Minimization | High | Reduce dependencies to keep examples focused |
| Setup Simplicity | High | Easy to run and experiment with |
| Learning Curve | High | Lower barrier to entry for learning |
| Code Readability | Medium | Clear, straightforward code is important |
| Flexibility | Medium | Ability to show different approaches |
| Production Readiness | Low | Learning value takes precedence over production features |

## Alternatives Considered

### 1. Plain Java ✅ Selected for Most Modules
- **Pros**: Minimal dependencies, focuses on core technology, easier to understand, faster to run
- **Cons**: Less production-ready, missing convenience features, manual configuration
- **Use Cases**: Event model, producer, basic consumers, simple processing

### 2. Spring Boot
- **Pros**: Production-ready features, auto-configuration, dependency injection, metrics, health checks
- **Cons**: More dependencies, learning Spring becomes part of the learning curve, obscures core technology
- **Use Cases**: Complex integration scenarios, production-like examples

### 3. Hybrid Approach ✅ Selected
- **Pros**: Best of both worlds, can show both simple and production-ready approaches
- **Cons**: Some code duplication, need to maintain both approaches
- **Decision**: Use plain Java for core examples, Spring Boot only where it demonstrates specific value

## Consequences

### Positive Consequences

1. **Technology Focus**: Plain Java implementations allow learners to focus on the core event processing technologies (Kafka, Esper, Flink) without the distraction of Spring Boot concepts.

2. **Reduced Dependencies**: Minimal dependencies mean smaller projects, faster builds, and fewer potential conflicts.

3. **Simpler Setup**: Plain Java applications are easier to set up and run, especially for learners new to event processing.

4. **Lower Learning Barrier**: Learners don't need to understand Spring Boot concepts to get started with event processing.

5. **Clearer Examples**: The code directly demonstrates how to use each technology's APIs without abstraction layers.

6. **Flexibility**: The hybrid approach allows us to introduce Spring Boot where it provides clear educational value (e.g., showing integration patterns).

### Negative Consequences

1. **Less Production-Ready**: Plain Java implementations may lack features important for production (metrics, health checks, configuration management).

2. **Manual Configuration**: Some configuration that Spring Boot would handle automatically must be done manually.

3. **Code Duplication**: In the hybrid approach, some concepts may be implemented in both styles.

4. **Limited Convenience Features**: Missing features like auto-reloading, dependency injection, and standardized configuration.

## Implementation Guidelines

### Use Plain Java For:

1. **event-model Module**: Pure data classes, no framework needed
2. **event-producer Module**: Demonstrate Kafka producer API directly
3. **kafka-consumer Module**: Demonstrate Kafka consumer API directly
4. **esper-cep Module**: Show Esper engine setup and rule definition
5. **flink-basic Module**: Demonstrate Flink DataStream API
6. **flink-cep Module**: Demonstrate Flink CEP pattern API

### Consider Spring Boot For:

1. **Complex Integration Scenarios**: When showing how technologies integrate in production-like environments
2. **Web-Based Examples**: If adding REST APIs for event inspection or management
3. **Configuration Management**: When demonstrating different configurations for the same processor
4. **Monitoring Examples**: When showing production monitoring and metrics

## Code Style Guidelines for Plain Java

### 1. Main Class Structure

```java
public class OrderEventProducer {
    private static final Logger logger = Logger.getLogger(OrderEventProducer.class.getName());
    
    private final KafkaProducer<String, String> producer;
    private final String topic;
    
    public OrderEventProducer(String bootstrapServers, String topic) {
        this.producer = createProducer(bootstrapServers);
        this.topic = topic;
    }
    
    public void produceEvent(OrderEvent event) {
        producer.send(new ProducerRecord<>(topic, event.getOrderId(), 
            EventSerializer.serialize(event)));
    }
    
    public void close() {
        producer.close();
    }
    
    public static void main(String[] args) {
        OrderEventProducer producer = new OrderEventProducer("localhost:9092", "orders");
        // Usage example
        producer.close();
    }
}
```

### 2. Configuration Management

Use simple property files or command-line arguments:

```java
// Load from properties file
Properties props = new Properties();
try (InputStream input = getClass().getResourceAsStream("/config.properties")) {
    props.load(input);
}

// Or use command-line arguments
String bootstrapServers = args.length > 0 ? args[0] : "localhost:9092";
```

### 3. Dependency Injection (Manual)

For complex scenarios, use constructor injection:

```java
public class EventProcessor {
    private final EventRepository repository;
    private final EventValidator validator;
    
    public EventProcessor(EventRepository repository, EventValidator validator) {
        this.repository = repository;
        this.validator = validator;
    }
    // ...
}

// Usage
EventRepository repo = new EventRepository();
EventValidator validator = new EventValidator();
EventProcessor processor = new EventProcessor(repo, validator);
```
